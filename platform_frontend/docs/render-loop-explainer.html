◧
h() / svg() build real DOM

h(tag, props, ...children) calls document.createElement and returns a real element — there is no virtual DOM. The "new tree" a view produces every render is a detached real DOM tree. svg() uses createElementNS(SVG_NAMESPACE, tag) (ADR-0047): an <svg> built with plain createElement is an HTMLUnknownElement and draws nothing.

Both record their authored props in a module-level WeakMap (NODE_PROPS, getProps/setProps), so render() can diff authored props next time — the live DOM exposes neither its attached listeners nor a portable attribute enumeration. applyProp is the single mapping table used at build time and reconcile time, so the two cannot drift.

It throws on innerHTML, on any /^on[A-Z]/ prop, and on class — but the real precondition matters: h()/svg() skip a prop whose value is null/undefined before applyProp runs, so those throws only fire for a non-nullish value. onAnswer: undefined is not caught. 

// applyProp's mapping table
on* + function  → addEventListener
SVG namespace   → setAttribute (className → class)
className       → el.className
value           → property
key in el       → property
else            → setAttribute

// two easy-to-miss real behaviours
<button> with no type → type="button" (SharePoint's page-wide <form>)
value applied last, after children (<select>.value set before its <option>s is silently discarded)
◍
The store owns state and scheduling

createStore({ initialState, reducer, onStateChange, schedule = queueMicrotask }). dispatch(action) runs the reducer synchronously and returns the new state, then schedules a notify. Notification is deferred and coalesced by a notifyScheduled latch: N dispatches in one turn produce exactly one onStateChange call, with the latest state.

flush() notifies synchronously — the shape the first mount needs — but it does not clear notifyScheduled: a dispatch made just before a flush still fires a second notify on the microtask.

The callback is onStateChange, not render, on purpose (ADR-0039) — the module is DOM-agnostic. dispatch schedules unconditionally: there is no equality check in store.js. A reducer returning the same object reference still notifies and still runs the view — what identity buys is that every memo() deps comparison hits and every prop diff finds nothing, so the commit touches no DOM. 

function scheduleNotify() {
  if (notifyScheduled || disposed) return;
  notifyScheduled = true;
  schedule(() => {
    notifyScheduled = false; // cleared before the call
    if (!disposed) onStateChange(state);
  });
}
◫
render() commits, and only render()

render(parent, tree, stats) patches parent's children in place and returns RenderStats; slices reach it as tools.render(container, tree). A render commit is one render(container, tree) call — one onStateChange turn (ADR-0039: view produces, render commits).

normalizeRoot accepts a node, an array, a DocumentFragment, or null/false, and throws TypeError('render(): view returned a string; wrap it in an element'). It never creates elements; it adopts builder-produced nodes and compares nodeName, which is why an HTML→SVG namespace change never compares equal. 

// core/render.js header
// Vocabulary: a **view** produces a tree of nodes and touches
// nothing; **render** commits a tree into a live container. This file is the
// one primitive that does the committing. It was called `morph()` once — the
// technique is the one morphdom and Idiomorph implement, and searching
// "DOM morphing" is still the way to read up on it.

Scene 02

        
How render() Reconciles

        

          Not a full replace.
          patchChildren(parent, newChildren, stats) matches
          survivors, removes the rest, and re-places with the fewest moves.
          Match rule sameType(a, b): same nodeName,
          and for elements the same key. keyOf(node) is
          node.getAttribute('key') behind an
          isText guard — authors pass { key } to
          h() and it lands as an attribute (because
          'key' in el is false), which means keys are stringified:
          key: 3 and key: '3' are the same key. A
          data-key
          alias was deliberately removed — one spelling on purpose.
        

        

          Keyed children match through an oldByKey map; unkeyed
          children match by position through a single advancing
          unkeyedPtr, and a positional candidate whose type
          mismatches is removed and rebuilt.
        

        

          Kept nodes are mutated, not replaced —
          patch() sets textContent for text nodes and,
          for elements, runs patchProps then recurses — so focus,
          caret, selection and scroll survive with no snapshot/restore
          machinery. patchProps unions the key sets of
          getProps(oldEl) and getProps(newEl),
          normalises null to undefined first (so
          'x' → null is a removal, not a no-op), skips unchanged
          values (ov === nv, why a referentially stable handler is
          never re-bound), calls removeProp then
          applyProp, then setProps(oldEl, newProps)
          so the next diff compares against what is now live.
          patchFormProp (HTML only) reconciles
          value/checked by comparing
          authored values: unchanged intent leaves the live value
          completely alone, so an unrelated re-render never clobbers an
          in-flight edit. placeChildren walks right-to-left and
          skips every index in
          longestIncreasingSubsequence(source), so nodes already in
          relative order are never touched.
        

        

          The honest limit: getProps returns
          undefined for nodes h() did not build, so
          patching over foreign DOM applies the new props but never removes that
          node's existing attributes.

Scene 03

        

          memo, the Reference Skip, and the Mount Lifetime
        

        

          createMemo() returns a callable
          memo(key, deps, viewFn) plus clear(),
          delete(key) and a size getter over a
          Map. A hit needs equal deps length and
          Object.is on each position. What it memoises is the
          node object itself — which, having been committed,
          is the live DOM node — so patch()'s
          short-circuit if (oldNode === newNode) return oldNode;
          skips the whole subtree: memo and the reconciler are one mechanism
          split across two files. That is exactly what the "memoise row 3"
          toggle above does — try it, then Shuffle: row 3's
          viewFn ran counter stops incrementing and
          stats.visited drops, because patch()
          returned on the reference check before it ever reached row 3's
          children.
        

        

          The cache is per mount, created by createStoreRoute and
          cleared in teardown, which is what stops keys colliding between routes
          and releases detached subtrees and their handlers. Sharp edge: the
          cache is unbounded within a mount and keyed by an author-chosen key,
          so two views sharing a key collide silently.
        

        

          Real call site —
          src/pages/question-bank/cora-bank-list.js memoises each
          Question Definition card on question.id:
        

        
props.memo(
  question.id,
  [
    question,
    bank.outcomeOptions,
    bank.labels,
    baselineQuestion,
    filters.questionGroup,
    conditional,
    questionTopology,
  ],
  view
)

        

          Why it is mandatory rather than an optimisation:
          ADR-0034, live Case Types reaching ~500 Question Definitions, and the
          measured result in docs/palimpsest-performance-gate.md —
          steady-state keystroke p95 0.30 ms against a ~5 ms
          tripwire.

          Error containment differs either side of mounted: before
          it, a render throw propagates out of mount(), the adapter
          disposes and rethrows, and the router's catch renders
          createRouteErrorPanel(); after it, commits run on a
          coalesced microtask with no try/catch on the path, so
          onStateChange contains it itself (log, dispose,
          container.replaceChildren(createRouteErrorPanel())).
          Effects: start(tools) may return a cleanup; every
          post-await dispatch is guarded with
          tools.isActive();
          withAbortSignal(client, tools.signal) binds reads to the
          mount lifetime and ignoreAbortError keeps an abort from
          becoming a toast; writes are never bound — SaveQueue
          holds the raw client.
        


        

          

            

              The router does not clear the container between pages
            

            

              Neither Router.navigate nor
              createStoreRoute.unmount clears it, so the next
              page's first commit reconciles against the previous page's
              leftover DOM. The consequence is the real lesson: matching root
              elements are patched in place, so the reconciler mutates the OLD
              node and discards the NEW one, and any reference a page cached to
              a freshly built node is left detached. Live workaround,
              src/pages/cora-case-review.js:724:
            

            
// The router leaves the previous route's DOM in the container; rendering
// over it would patch those foreign nodes in place and leave this shell's
// cached part references detached. A fresh mount replaces the content
// outright so every later per-part render targets in-document nodes.
container.replaceChildren(root);

            

              This is not only-on-error-paths use:
              container.replaceChildren(...) also appears on the
              two failure paths above — this is a third, deliberate use, for a
              healthy mount.

An unmatched hash returns early

            

              Router.navigate returns before the unmount when
              nothing matches, so an unknown hash leaves the previous page
              mounted with its effects still running.
            

          


          

            
A slice may own its own commit

            

              slice.render(container, state, tools) wins over
              slice.view when present;
              src/pages/cora-my-stats.js uses it to commit and then
              mount the HTML-over-SVG tooltip controller against the freshly
              committed chart. A slice with neither throws
              TypeError('Store route slice must define view() or
                render()').
