Leaf Operators

The atom of showWhen. Each leaf names exactly one question ID and one operator. evalOp() handles all three.

showWhen: { 'q-needs': { equals: 'Yes' } } showWhen: { 'q-channel': { in: ['Phone', 'Chat'] } } showWhen: { 'q-notes': { answered: true } }
⌥
$and / $or

Logical combinators. Each element of the array is itself a full condition — evalCondition() recurses, so combinators nest to any depth.

showWhen: { $and: [ { 'q-needs': { equals: 'Yes' } }, { 'q-channel': { in: ['Phone'] } } ]} showWhen: { $or: [ ... ] }
∞
No showWhen

Questions without a showWhen key are always applicable. The framework checks !q.showWhen || evalCondition(...) — absence is treated as unconditional truth, not an error.

{ id: 'q-welcome', text: 'Was the customer greeted?', // no showWhen → always in the Set }

Cycle Detection — DFS at Load Time

Before the framework mounts a Case Type, it runs detectCycles(): a depth-first search that colours each node WHITE → GRAY → BLACK. A back edge to a GRAY node means a cycle — the framework refuses to mount.
