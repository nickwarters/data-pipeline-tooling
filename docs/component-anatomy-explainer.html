CORA / page anatomy / ADR-0034

State in.
DOM out.
Actions back.

Maintainer field note · July 2026

A page is a small loop with explicit ownership. State describes the screen. A pure view turns it into safe light DOM. User events dispatch actions. The reducer returns the next state.

Views are synchronous.
Effects cross boundaries.
The route adapter owns lifecycle.
There is no second state system.
01

State

One route-local object: shared chrome plus one named page slice.

02

View

A deterministic function returns an h() node tree.

03

Action

A callback dispatches a fact named domain/event.

04

Reducer

A pure transition returns the next state; rendering is coalesced.

The route slice

Four exports tell the story.

  1. A state shape with one route key
  2. A pure view with dispatch callbacks
  3. A reducer with immutable transitions
  4. A factory that joins state, reducer, view, and effects
src/pages/greeting.js public page seam 
import { h } from '../lib/html.js';

export function greetingView(state, { dispatch }) {
  const { name } = state.routes.greeting;
  return h(
    'main',
    { className: 'cora-greeting' },
    h('h1', {}, name ? `Hello, ${name}` : 'Hello'),
    h('input', {
      value: name,
      oninput: (event) => dispatch({
        type: 'greeting/name-changed',
        name: event.currentTarget.value,
      }),
    })
  );
}

export function greetingReducer(state, action) {
  if (action.type !== 'greeting/name-changed') return state;
  return {
    ...state,
    routes: {
      ...state.routes,
      greeting: { ...state.routes.greeting, name: action.name },
    },
  };
}

export function createRouteSlice(_params, context) {
  return {
    initialState: {
      chrome: context.chrome,
      routes: { greeting: { name: '' } },
    },
    reducer: greetingReducer,
    view: greetingView,
    // Optional start(tools) owns I/O and cleanup.
  };
}

Inside the view

Render and dispatch

Read state, compose pure child views, return h() nodes, and dispatch actions from event callbacks.

Inside effects

Cross the edge

Load through SharePointClient, persist through SaveQueue, await work, then dispatch the result.

Inside the adapter

Render and clean up

createStoreRoute() owns the store, keyed render(), memo cache, listeners, errors, and teardown.

Before the route ships

  • Page import lives in the route table, nowhere else
  • State is under { chrome, routes }
  • View is pure and synchronous
  • Events dispatch named actions
  • Reducer does not mutate prior state
  • I/O lives in an effect
  • External listeners use listen()
  • Tests prove public behaviour
